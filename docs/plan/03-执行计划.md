# HP102 职业导航智能体 · 执行计划（最小执行单元）

> 执行规则见 [README.md](README.md)。**每个任务开一个新对话**，完成即 commit 并更新 `PROGRESS.md`。
> 路径约定：`<HP102>` = `D:\_workspace\01_项目-Coding\HP102-职业导航智能体-career-nav-agent`，`<A300>` = `D:\_workspace\01_项目-Coding\A300-职业导航-career-nav`（只读），`<A500>` = `D:\_workspace\01_项目-Coding\A500-薪资查询-salary-report`（只读）。所有命令在 `<HP102>` 下用 PowerShell 执行。
> “02 §x” 指 [02-技术方案.md](02-技术方案.md) 的章节。

## 任务格式

每个任务包含：**前置**（必须已完成的任务）、**必读**、**产出**（新增或修改的文件，一般 3–5 个）、**先写测试**（测试文件与具体用例：输入 → 期望结果）、**步骤**、**验收**（命令 + 期望结果）、**完成定义**、**不要做**。

做法固定为：先按“先写测试”写好测试并确认它失败（或无法编译）→ 再写实现 → 跑验收。

## 通用完成定义（每个任务都要满足，任务里只写额外条目）

1. 本任务列出的测试全部通过。
2. `npm run typecheck` 0 错误；`npm run lint` 0 错误。
3. `npm test` 全部通过（不能弄坏之前任务的测试）。
4. 只改了“产出”列出的文件（`package-lock.json`、`next-env.d.ts` 等自动生成文件除外）。
5. `git add -A` 并 `git commit -m "T编号: 任务名"`。
6. `PROGRESS.md` 中本任务：状态改为“完成”，“验收证据”写实际结果（例如 `scoring.test.ts 5 passed；typecheck/lint 0`）。

## 通用不要做

- 不修改 A300、A500、HP101 或工作区其他项目的任何文件。
- 不新增“产出”和 02 §2 以外的依赖（不装任何模型 SDK）。
- 不提前做后续任务的内容；不为了让测试通过去修改之前任务已定的测试期望。
- 不在终端、日志、测试、提交里输出任何密钥；不搜索、不读取工作区凭证保险柜。

## 常用命令

| 目的 | 命令 |
|---|---|
| 跑单个单元测试文件 | `npm test -- tests/unit/<文件名>.test.ts` |
| 跑单个界面/接口测试（桌面） | `npx playwright test tests/e2e/<文件名>.spec.ts --project "Desktop Chrome"` |
| 类型检查 / 代码检查 | `npm run typecheck` / `npm run lint` |
| 构建 | `npm run build` |
