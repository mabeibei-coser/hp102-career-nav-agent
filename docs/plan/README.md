# HP102 职业导航智能体 · 实施计划包（执行入口）

本目录是 HP102 的完整需求、技术方案和分步执行计划，写给**执行模型**（例如 flash 类模型）照着做。规划日期：2026-09-24。

## 阅读顺序

1. [01-需求方案.md](01-需求方案.md)：做什么、给谁用、每一步用户看到什么、红线和验收标准。
2. [02-技术方案.md](02-技术方案.md)：怎么做。架构、目录、数据表、接口、智能体循环、Skill 说明书、工具定义、从 A300 复用哪些代码。
3. [03-执行计划.md](03-执行计划.md)：按顺序执行的最小任务清单（共 63 个）。每个任务写明前置任务、必读、产出文件、先写的测试用例、验收命令、完成定义和不要做的范围。
4. [PROGRESS.md](PROGRESS.md)：进度表，编号与 03 完全一致。每完成一个任务就更新。

开工前三份文档都要读完。执行时以 03 为准；03 里引用了 02 的章节编号（如「见 02 §8.3」）。

## 执行总规则（必须遵守）

0. **每个任务开一个新对话**。新对话开始时读本文件、`PROGRESS.md` 和 03 中该任务一节（以及它“必读”列出的内容）；任务完成即 commit 并更新 `PROGRESS.md`，然后结束这个对话。
1. **一次只做一个任务**，严格按 03 的编号顺序，前置任务未完成不开始。先写测试，再写实现；跑该任务的全部验收命令，全部通过才 `git commit`，然后更新 `PROGRESS.md`。提交信息格式：`T1.9: 题库与计分`。
2. **什么时候必须停下来问用户**：
   - 文档没写到、而且会改变方向的事：换库或新增依赖、改数据表含义、改业务规则、改用户可见流程、改红线；
   - 03 中标注【需用户确认】的步骤；
   - 同一个验收失败连续修 3 次仍不通过。停下时写清：卡在哪一步、看到了什么、你怀疑的原因。
   细节问题（变量命名、样式微调、文案标点）自己决定，在 `PROGRESS.md` 备注一句即可。
3. **A300、HP101 只读**。只从里面读代码、复制代码，不修改它们的任何文件，也不在运行时依赖它们（不 import 它们的路径，不请求它们的线上接口）。
4. **密钥**：模型 Key `BANANAROUTER_API_KEY` **由用户**写进 HP102 的 `.env.local`（03 T1.16【需用户确认】）。执行模型**不得**自行搜索或读取工作区凭证保险柜，也不要去其他项目找 Key；不在终端打印、不写进任何文档/日志/测试/提交。`.env.local` 必须被 `.gitignore` 忽略。第 2 期 T2.5 再从 A300 `.env.local` 复制语音相关变量。不从 A300 复制任何模型相关变量。BananaRouter Key 与工作区已迁移的项目共用，上线前确认是否单独申请或走凭证中心取件。
5. **测试不花钱**：单元测试和 E2E 一律 `E2E_MOCK_MODE=true`。只有 03 中标注【真实模型】的步骤才调用真实接口，且按标注的次数上限执行。
6. **生产代码里不允许用假内容顶替失败**。模型调用失败 = 明确告诉用户失败并允许重试。mock 只存在于测试模式（02 §7.8）。V1 没有兜底模型；切换服务商只能由用户决定（02 §18）。
7. **禁止做的事**：部署到服务器、推送到远端仓库、修改 admin-hub（B100）、删除任何历史文件。除非用户明确下令。
8. **Next.js 16 与训练数据不同**：写 Next.js 相关代码前，先读 `node_modules/next/dist/docs/` 里对应章节（路由处理器、`after`、`instrumentation`、`cookies`），遵循其中的弃用提示。
9. **环境**：Windows + PowerShell，路径含中文。读写文本一律 UTF-8；PowerShell 里用 `-LiteralPath` 和 `-Encoding UTF8`。
10. **代码风格**：TypeScript 严格模式；不写“这行代码做什么”式的注释，也不写“来自 A300”的来源注释（来源已记录在 02 §15）。只在代码无法自己表达的约束处写注释。
11. **分层规矩**（Coding 域通用规则）：业务规则只写在 `lib/career/`；数据库读写只写在 `lib/db/`；模型调用只写在 `lib/llm/`；API 路由只做身份、参数校验、调用用例、转换结果。

## 已经定下来的决策（不要自行更改）

| 决策 | 结论 |
|---|---|
| 项目名 / 路径 | `HP102-职业导航智能体-career-nav-agent`，线上子路径 `/hp102`（域名部署时再定） |
| 与 HP101 关系 | 独立新项目，只做职业导航，轻量栈；不复用 HP101 的 PostgreSQL / 队列 / Harness |
| 智能体底层 | 用原生 `fetch` 调 Gemini 原生接口，手写函数调用循环；循环只依赖中立的适配器接口（02 §7.5），不感知服务商。不引入任何模型 SDK，不用 Harness、Vercel AI SDK、CopilotKit、assistant-ui、LangGraph 等框架 |
| 回复方式 | V1 非流式：整段返回，接口是普通 JSON，不用 SSE；前端等待时显示“正在思考…”。逐字流式是 V2 可选项 |
| 流程推进方式 | 混合：模型通过受控工具推进，每条用户消息最多 3 次工具调用；确认档案、生成报告、确认重新开始只能由用户点卡片（人在回路） |
| 消息落库 | 一轮对话结束后在一个事务里写入本轮全部消息；中途模型失败整轮不落库 |
| 模型 | BananaRouter 中转的 Gemini 原生接口 `generateContent`，模型 `gemini-3.1-flash-lite`，与工作区已上线的 A200/A500/A600/A900 做法一致；对话 `thinkingLevel: "minimal"`，严格遵守思考签名规则（02 §7.6）；**禁用** BananaRouter 的 `/v1/chat/completions`；**V1 没有兜底模型**。先由 T1.16 冒烟实测工具调用，不通过时停下由用户决定是否切到备选方案（02 §18） |
| 凭证 | 三个环境变量 `BANANAROUTER_API_KEY`、`BANANAROUTER_BASE_URL`、`BANANAROUTER_MODEL` 都必须显式配置，缺一个启动即报错，没有默认值；Key 由用户写入 `.env.local`，执行模型不碰保险柜 |
| 技术栈 | Next.js 16 + React 19 + TypeScript + Tailwind v4 + better-sqlite3（WAL）+ iron-session + zod；模型调用用原生 `fetch` |
| 业务口径 | 以 A300 为准：4 维度 / 6 能力 / 5 模块报告 / 身份与年龄口径 / 红线词 |

另有几项“默认决定”写在 01 §11，用户可能会改；改了以用户为准。
